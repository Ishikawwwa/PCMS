# Generality is a release criterion

The goal is a useful constraint memory layer that can outperform authentic MAGE
under a matched protocol. Improving one repeatedly inspected travel family does
not establish that goal. The latest E3I run passed two of six full plans versus
one of six for E0; both complete-group success rates are zero. Family 6 remains
development data, including all its request paraphrases and renamed variants.

The later seven-family E1/E2 development screen is now complete. E1 passes
18/49 full traveler plans and E2 passes 16/49, with complete-group SR zero for
both. The current dependency-closure policy is not promoted. Together with the
9/10 versus 8/10 free-form result, this supports keeping a competent ledger as
the control and requiring new evidence for added memory machinery. It does not
establish broad constraint-memory efficacy or compare against authentic MAGE.
See `cross_family_completion/analysis.md` for context pressure, completion caps,
uncertainty and the disclosed infrastructure recovery. No task-family IDs or
expected answers from these inspected examples may enter the reusable memory
implementation as a substitute for independent transfer evaluation.

The reusable `ConstraintMemory` API accepts opaque references, observed JSON
facts, explicit task contracts, causal versions and units. It retains actual
actions and evidence, resolves LIVE or explicit SNAPSHOT bindings, protects
consumed entity ancestry, and reports missing, conflicting or stale evidence as
UNVERIFIED. It has no traveler, city, day, accommodation, benchmark-family or
answer logic. The comparison kernel is also used by the travel adapter.

The E3R travel candidate still uses the existing travel ledger and limited
request grammar. The portable API is a separate implementation sharing the
comparison kernel; its tests do not establish generality of that live adapter.
Travel parsing, city aliases, full-name handling and declared inheritance stay
in adapters and are disclosed protocol factors. The optional USD interpretation
is an explicit shared experiment schema, not a currency certified by the CSV.

Natural-language model extraction is advisory unless a separate adapter verifies
an individual interpretation. An exact quote or valid JSON does not certify
meaning. Unsupported wording is preserved for the planner and remains
UNVERIFIED. Internal consistency never sets overall task success to true.

## Evidence and next tests

Independent deterministic workflows cover scheduling, procurement, deployment
and inventory; resource renaming, different JSON layouts and numeric
representations; revisions, stale properties, mixed units, contradictory
observations and unsupported interpretation. They test API mechanics with
scripted actions. They do not measure Qwen's ability to extract or follow
constraints in those domains.

`scripts/run_portable_transfer.py` prepares a separate model diagnostic. Its
36 disclosed synthetic development inputs cover four domains, three memory
renderings, short histories, context pressure and infeasible offers. Offered
identities are opaque and order is varied. Both conditions receive the
same current offers and task; HISTORY retains chronological evidence under the
same 4096-token cap, while CONSTRAINT uses protected current bindings. Every
option property is grounded in an already observed row. Evaluation occurs only
after the submitted option and never supplies repair feedback. One model call
per case/condition uses the same Polza Qwen model and settings. No expected
option ID is stored in task inputs.

This diagnostic uses explicit structured input contracts, a deliberately weak
recent-history truncation control, and a scorer sharing the comparison core.
Pressure cases intentionally expose retention loss. Formatting variants reuse
the same underlying tasks and are not independent samples. Passing them cannot
establish broad agent generalization, natural-language interpretation, or MAGE
superiority. A semantic-summary or relevance-retrieval baseline, an independent
scorer, free-form tasks and independently authored unseen workflows are required
before promoting this into an efficacy benchmark.

## Promotion rule

1. Freeze source, prompts, inference, memory budgets, cost limits and methodology
   before validation. Keep original runs immutable. Record every shared adapter
   factor and charge maintenance and repair costs.
2. Keep all inspected families and generated examples in development. Use the
   existing disjoint validation families for selection; open the final holdout
   once after freezing. A paraphrase of an inspected task stays development.
3. Test unseen workflows and independently written free-form requests, reordered
   facts, partial tool results, multiple constraints, revisions, negation,
   conditionals, uncertainty and infeasible requests. Measure extraction
   faithfulness, unsupported-semantics coverage, action constraint satisfaction,
   whole-task success, recovery effects, tokens and latency separately.
4. Report results by domain, underlying task family and format. Pair conditions
   and cluster uncertainty by underlying family. Never count renderings as
   independent wins or promote a candidate on the repeatedly inspected family.
5. Require a benefit beyond capped recent history and a matched authentic MAGE
   comparison. Accept simplification if a flat ledger or simpler retrieval
   performs equally well. A travel-only benefit must be described as travel-only.

The terminal structured run `portable-transfer-20261014T191914Z` saved 59 of
72 conditions before crossing its 20 RUB threshold. Exact ledger cost is
20.12386276 RUB. Archived-code replay and a separate Fraction/set oracle reproduce
all saved results. On 29 complete pairs, CONSTRAINT passes 29 and HISTORY passes
20; one additional unpaired CONSTRAINT result passes. Missing conditions remain
missing. Every difference is a pressure task where HISTORY lost the supplied
policy/revision. This is evidence for explicit-binding retention under that
control, not broad semantic transfer. See the partial verification report.

The new `experiments/freeform_memory/` prototype uses ten disclosed natural-language
workflows and the existing portable API. FACT_LEDGER and ADVISORY_IR retain the
same raw user requirements, current facts and fact revisions. The latter adds
fallible model-written predicates with exact quotations, while conditionals and
unsupported wording remain raw and advisory. Maintenance calls count against the
same suite ledger. No benchmark traveler/day grammar is used in that runtime.
Caller-provided schema bindings and units are still required; autonomous schema
discovery is not tested. Offline annotations are read only after durable actual
action commitment by a separate evaluator that does not import the memory core.

These ten workflows were authored during development, not obtained from an
untouched external test source. The complete run `freeform-transfer-20261015T182535Z`
has now been independently verified: FACT_LEDGER passes 9/10 and ADVISORY_IR 8/10,
with no IR-only wins. IR costs 4.84335275 RUB against 3.03146738 for the ledger.
Every required raw/factual section is identical, all memory fits under the cap,
and an independent oracle agrees with every actual verdict. Accepted IR can
still have semantic errors; successful actions often follow the retained raw
instructions instead. No accepted SNAPSHOT interpretation reached a planner.
The advisory writer is not promoted. See `freeform_live_verification/summary.md`.

These are measured development outcomes, not evidence of broad multi-action
transfer or superiority over MAGE. Retain the strong ledger and test whether
constraint mechanisms add value beyond it on new independently authored data.
Do not treat case-specific patches and regrading this disclosed set as new
generalization evidence. The next frozen seven-family E1/E2 travel comparison
tests current closure policy under shared factors and a generous primary memory
ceiling; it does not establish free-form semantic extraction by itself.
